# Conventions

These rules apply to every endpoint in the API reference.

## Base URL and format

All requests use HTTPS and the base URL `https://api.arena.example/v1`. Request and response bodies are JSON. Send `Content-Type: application/json` on requests with a body. Timestamps are ISO 8601 in UTC.

## Errors

The API uses standard HTTP status codes. Error responses share one shape.

```json
{
  "error": {
    "type": "invalid_request_error",
    "code": "missing_parameter",
    "message": "display_name is required.",
    "param": "display_name",
    "request_id": "req_a1b2c3"
  }
}
```

## Pagination

List endpoints return a page of objects and use cursors.

```bash
curl "https://api.arena.example/v1/players?limit=25" \
  -H "Authorization: Bearer sk_test_YOUR_KEY"
```

```json
{
  "object": "list",
  "data": [],
  "has_more": true,
  "next_cursor": "cur_8f3a"
}
```

<ParamTable
  rows={[
    { name: 'limit', type: 'integer', desc: 'Objects per page, from 1 to 100. The default is 25.' },
    { name: 'cursor', type: 'string', desc: 'Pass next_cursor from the previous response to get the next page.' },
  ]}
/>

When `has_more` is `false`, you have reached the end. Cursors expire after 24 hours.

## Idempotency

Send an `Idempotency-Key` header on every `POST` request that creates or changes something. If a request times out, retry it with the same key and the API will not repeat the action.

```bash
curl https://api.arena.example/v1/purchases \
  -H "Authorization: Bearer sk_test_YOUR_KEY" \
  -H "Idempotency-Key: purchase-0001" \
  -H "Content-Type: application/json" \
  -d '{"player_id": "plr_123", "item_id": "itm_gold_pack", "quantity": 1, "payment_token": "tok_test_success"}'
```

- Use a unique key per logical action, such as a UUID or an ID from your own system.
- Keys are remembered for 24 hours.
- Reusing a key with different parameters returns `409` with the code `idempotency_key_reuse`.
- `GET` and `DELETE` requests are naturally idempotent and ignore the header.

On a `429`, wait for `Retry-After` seconds, then retry. Add random jitter so many clients do not retry together.

## Versioning

The API is versioned by date. Your account is pinned to the version that was current when you created your first key. To test a newer version on one request, send the header `Arena-Version: 2026-10-01`.

Backward-compatible changes ship without a new version. These include new endpoints, new optional parameters and new fields in responses. Write your client to ignore fields it does not recognize.

## Object IDs

IDs are opaque strings with a prefix that shows the type, such as `plr_123` for a player. Do not parse them or assume a length.
