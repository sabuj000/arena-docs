# Sandbox and test data

Every account has a sandbox. Requests made with a `sk_test_` or `pk_test_` key run against sandbox data and never affect live players, balances or leaderboards.

## What is different in the sandbox

- Data is isolated from live mode. Object IDs are valid in one mode only.
- Webhooks are delivered to your test endpoints.
- Rate limits are lower. See [Conventions](/docs/api/conventions#rate-limits).
- Sandbox data can be reset at any time from the dashboard.

## The demo sandbox

Arena has no hosted service, but the demo sandbox in the [arena-game repository](https://github.com/sabuj000/arena-game) implements every operation in this reference. It runs in your browser or in Node. You can [send requests to it from a web page](https://sabuj000.github.io/Portfolio/arena-api.html), and the [demo games](https://arena-game-sooty.vercel.app) use it. It is separate from the test mode described on this page:

- It keeps its data in your browser, or in memory in Node. Call `sandbox.reset()` to start again.
- It has no dashboard. It does not deliver webhooks or enforce rate limits.
- It has more seed data than listed below, such as a leaderboard for each demo game.
- It supports `tok_test_success` and `tok_test_declined`, but not `tok_test_slow`.
- It supports idempotency keys.

## Seed data

New sandboxes include:

- Two leaderboards: `weekly` (highest score wins) and `all_time`.
- Three items: `itm_gold_pack`, `itm_arena_skin` and `itm_season_pass`.
- Two achievements: `first_win` and `ten_wins`.

## Reset the sandbox

Resetting deletes all sandbox players, matches, scores, inventory and purchases, then restores the seed data. API keys and webhook endpoints are kept.

<Callout type="warning">
  A reset cannot be undone. Live data is never affected.
</Callout>

## Move to live

1. Create a live server key.
2. Replace `sk_test_` keys in your production configuration.
3. Register your live webhook endpoint.
4. Re-create any items and achievements you configured in the sandbox.
