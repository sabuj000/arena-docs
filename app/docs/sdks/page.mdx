# SDKs

<Callout type="note">
  Arena is a fictional API, so there are no published SDKs and no real servers. The demo TypeScript SDK below works only against a sandbox that runs in your browser or in Node.
</Callout>

## TypeScript SDK (demo)

The TypeScript SDK is generated from the Arena OpenAPI spec and covers all 28 operations in 6 resources. It has no runtime dependencies. It lives in the [arena-game repository](https://github.com/sabuj000/arena-game), together with a sandbox that implements the API and a small game that uses both.

There is no package to install. Copy the `sdk/` folder into your project, or clone the repository. The repository runs its TypeScript directly with Node.js 22.6 or later.

### Make a first request

This example runs the SDK against the in-memory sandbox, so it needs no network and no account. It creates a player and submits a score, as in the [Quickstart](/docs/get-started/quickstart).

```ts
import { Arena } from './sdk/index.ts'
import { createSandbox } from './sandbox/sandbox.ts'
import { memoryStorage } from './sandbox/store.ts'

const sandbox = createSandbox({ storage: memoryStorage() })
const arena = new Arena({ apiKey: 'sk_test_demo', fetch: sandbox.fetch })

const player = await arena.players.create({ display_name: 'NovaKnight' })
const score = await arena.leaderboards.submitScore('weekly', { player_id: player.id, score: 2400 })
console.log(score.rank)
```

To point the SDK at a server, leave out `fetch` and set `baseUrl`. The default base URL is `https://api.arena.example/v1`, which does not exist.

<Callout type="warning">
  Keep secret keys (`sk_`) on your server. The demo game puts a sandbox key in the browser only because the sandbox is not a real service. A real game must never ship a secret key.
</Callout>

### Retries and idempotency keys

The SDK retries a request after a network error, a `429` response or a `500` response, up to `maxRetries` times. For a `429` it waits for the `Retry-After` header, or one second if the header is missing. For the other two it waits with exponential backoff that starts at about 500 ms. It does not retry other `5xx` statuses or any `4xx` status. When the retries run out after a network error, it throws `ArenaConnectionError`.

The SDK sets an `Idempotency-Key` header on every `POST` request and uses the same key for each retry of that request, so a retry cannot repeat an action such as a purchase. To choose the key yourself, pass `{ idempotencyKey }` as the last argument. See [Errors and retries](/docs/guides/errors-and-retries) for the underlying rules.

### Errors

A response with a status of 400 or higher throws `ArenaError`. It has `status`, `type`, `code`, `param` and `requestId`, which match the [error object](/docs/api/conventions). Branch on `code`, not on the message.

```ts
import { ArenaError } from './sdk/index.ts'

try {
  await arena.players.create({ display_name: 'ab' })
} catch (error) {
  if (error instanceof ArenaError && error.code === 'invalid_display_name') {
    // Ask the player for a longer name.
  }
}
```

### Pagination

List calls return `data`, `has_more` and `next_cursor`. The `paginate` helper walks every page.

```ts
import { paginate } from './sdk/index.ts'

for await (const player of paginate((cursor) => arena.players.list({ limit: 50, cursor }))) {
  console.log(player.display_name)
}
```

### Known limits

- The OpenAPI spec does not describe the body of list responses, the leaderboard entry responses, or the achievement unlock response. The SDK defines those types itself, so they can differ from a future spec.
- The sandbox is not Arena. It is an implementation written for this demo, checked against the spec by a contract test.

## Call the API directly from any language

Arena is a standard JSON REST API. Any HTTP client works.

<CodeGroup>

```bash
curl https://api.arena.example/v1/players \
  -H "Authorization: Bearer sk_test_YOUR_KEY" \
  -H "Content-Type: application/json" \
  -d '{"display_name": "NovaKnight"}'
```

```ts
const res = await fetch('https://api.arena.example/v1/players', {
  method: 'POST',
  headers: {
    Authorization: `Bearer ${process.env.ARENA_SECRET_KEY}`,
    'Content-Type': 'application/json',
  },
  body: JSON.stringify({ display_name: 'NovaKnight' }),
})
const player = await res.json()
```

```python
import os
import requests

res = requests.post(
    "https://api.arena.example/v1/players",
    headers={
        "Authorization": f"Bearer {os.environ['ARENA_SECRET_KEY']}",
    },
    json={"display_name": "NovaKnight"},
    timeout=10,
)
player = res.json()
```

```php
<?php
$ch = curl_init('https://api.arena.example/v1/players');
curl_setopt_array($ch, [
    CURLOPT_POST => true,
    CURLOPT_RETURNTRANSFER => true,
    CURLOPT_HTTPHEADER => [
        'Authorization: Bearer ' . getenv('ARENA_SECRET_KEY'),
        'Content-Type: application/json',
    ],
    CURLOPT_POSTFIELDS => json_encode(['display_name' => 'NovaKnight']),
]);
$player = json_decode(curl_exec($ch), true);
curl_close($ch);
```

</CodeGroup>

The TypeScript example uses the built-in `fetch` in Node.js 18 or later. The Python example uses the `requests` package. The PHP example uses the cURL extension.
